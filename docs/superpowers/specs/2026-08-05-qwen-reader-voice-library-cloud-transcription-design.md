# Qwen Reader 音色库、批量导入与 Edge 云识别设计

## 目标

在现有 Qwen Reader Manifest V3 扩展的“音色录制室”中补齐音色库管理能力，同时保持现有本地 Qwen Vulkan TTS 架构不变：

- 保留浏览器麦克风录音并注册音色的现有功能。
- 支持单个或批量导入 WAV、MP3、M4A、AAC、OGG 音频。
- 浏览器自动解码、裁剪静音并选取适合克隆的 5～15 秒片段。
- 默认使用 Microsoft Edge 的 `SpeechRecognition` 云服务自动识别参考台词。
- 识别结果始终可编辑；识别失败不阻止保存音频或继续处理同批文件。
- 文件名去掉扩展名后作为默认音色名；重名自动追加 ` (2)`、` (3)`。
- 本地录制音色支持重命名，并同步修复楼主音色和回复音色配置。
- 不安装 Whisper、不新增托盘图标、不增加开机启动程序。

## 非目标

- 不把语音识别模型集成进扩展包。
- 不创建 Azure Speech 账户，不要求 API Key。
- 不承诺 Edge 云识别的服务等级、永久免费额度或离线能力。
- 不在这一阶段加入说话人分离、自动判断角色或长音频全文转写。
- 不修改现有 Qwen TTS 模型、Vulkan 后端、端口或十分钟自动卸载机制。

## 当前基础与约束

- 音色工作室已有麦克风录音、24 kHz 单声道 WAV 编码、保存、列出和删除功能。
- 音色配置保存在 `chrome.storage.local` 的 `voiceProfiles` 中。
- 后端音色注册接口为 `POST http://127.0.0.1:7811/v1/audio/voices`。
- 注册载荷已经支持 `ref_text`，但当前 UI 没有采集或识别台词。
- 内置音色和兼容别名不一定包含可重新注册的参考音频，因此只能重命名用户本地保存的音色。
- Edge 云端 Web Speech 实现会把音频发送到微软服务；UI 必须明确提示这一点。

## 方案选择

### 默认方案：Edge Web Speech 云识别

扩展直接使用 Edge 的 `SpeechRecognition` API，不需要 API Key、Azure 账户或额外常驻进程。上传音频通过 Web Audio 路由到 `MediaStreamDestination`，把音轨传入 `recognition.start(audioTrack)`。

选择理由：

- 用户当前使用 Edge 151，版本足够新，并且网络稳定。
- 参考片段只有 5～15 秒，实时识别带来的等待可以接受。
- 不增加本地模型、显存占用、托盘程序或维护负担。
- 识别只是辅助填写台词；结果可编辑，因此不要求百分之百准确。

### 保留的替换边界

语音识别封装为独立 `TranscriptionProvider`。当前只实现 Edge Provider，但 UI 和批量任务不得直接依赖具体 API。将来如果 Edge 服务不可用，可以增加 Azure Key 或本地 Whisper Provider，而不重写批量导入和音色库。

## 用户界面

音色工作室调整为三个清晰区域：

1. **录制音色**：保留开始录音、停止、试听和命名；停止录音后自动发起台词识别。
2. **导入音色**：支持拖放、选择文件和批量选择；接受 WAV、MP3、M4A、AAC、OGG。
3. **我的音色库**：显示名称、参考台词、来源、时长和状态，提供试听、重命名、删除操作。

批量导入使用任务表格，每行包含：

- 文件名与格式。
- 可编辑的音色名称。
- 原始时长和最终片段时长。
- 可编辑的识别台词。
- 状态：等待、正在处理、识别中、可保存、保存中、成功、失败。
- 单行重试、跳过和移除操作。

批量顶部提供“全部保存”和“取消处理”。取消只停止尚未完成的任务，不删除已经保存成功的音色。

在导入区常驻显示隐私提示：自动识别会把选定的参考片段发送到 Microsoft 云服务；Qwen 音色和网页朗读仍然使用本机服务。

## 音频处理

### 解码和格式统一

浏览器使用 `AudioContext.decodeAudioData()` 解码导入文件，将多声道下混为单声道。用于 Qwen 注册的最终音频统一编码为：

- 24 kHz。
- 单声道。
- PCM 16-bit WAV。

不能被浏览器解码、没有有效音频帧或内容损坏的文件只标记该行失败，不中断整个批次。

### 静音裁剪和片段选择

处理器以短帧计算 RMS 能量并估算当前文件的噪声底：

1. 去掉明显的首尾静音。
2. 在剩余音频中寻找语音活动连续、响度稳定且没有削波的窗口。
3. 音频超过 15 秒时选取得分最高的 10～15 秒窗口。
4. 裁剪后在 5～15 秒之间时直接使用。
5. 有效语音不足 5 秒时不自动注册，提示用户换文件或重新录制。

算法只选择片段，不做降噪、变声、响度压缩或语音增强，避免改变说话人的音色特征。

## 台词识别

### 数据流

1. 用户通过明确点击或拖放加入音频。
2. 浏览器完成解码、静音裁剪和最佳片段选择。
3. 选定片段连接到 Web Audio 的 `MediaStreamDestination`。
4. `SpeechRecognition` 使用 `zh-CN`、连续结果和最终结果模式识别该音轨。
5. 合并最终结果、整理空白后填入该行台词输入框。
6. 用户可以修改台词，然后注册音色。

不设置 `processLocally = true`。当前设计明确使用 Edge 默认云服务，以免依赖试验性的本地模型和有限的本地语言支持。

### 批量调度

- 同一时间只运行一个识别任务。
- 每个任务的超时为片段时长加 15 秒。
- 用户取消批次时停止当前识别并清空未开始的识别任务。
- 识别结束后立即释放音轨、AudioNode、对象 URL 和临时缓冲区。

### 重试规则

以下临时错误最多自动重试两次，等待约 1 秒和 3 秒：

- `network`
- 非用户主动触发的 `aborted`
- 首次出现的 `no-speech`
- 服务无结果或超时

以下错误不自动重试：

- 用户拒绝权限或浏览器策略禁用服务。
- `language-not-supported`、`service-not-allowed`。
- 浏览器没有 `SpeechRecognition` 或不接受音轨参数。
- 音频无法解码或有效语音不足 5 秒。

最终失败时保留已处理的 WAV 和音色名称，台词框为空并显示“可手动填写”。用户可以单独重试识别，也可以用空台词保存；空台词会回到仅说话人特征克隆模式。

## 命名、保存与数据模型

### 默认名称和重名

- 默认名称为文件名去掉最后一个扩展名后的结果。
- 清理首尾空白、控制字符和不能作为后端名称的字符。
- 名称为空时使用“未命名音色”。
- 名称和现有音色或同批任务冲突时依次生成 `名称 (2)`、`名称 (3)`。
- 用户手动修改名称后重新执行冲突校验。

### 本地配置

新保存的 profile 在兼容现有字段的基础上增加元数据：

```js
{
  name,
  wavB64,
  mimeType: "audio/wav",
  sampleRate: 24000,
  refText,
  sourceFileName,
  durationSeconds,
  createdAt,
  updatedAt,
  transcription: {
    provider: "edge-web-speech",
    status: "recognized" | "manual" | "failed" | "skipped",
    attempts
  }
}
```

现有不含这些字段的 `voiceProfiles` 继续可用，不强制迁移。

### 保存顺序

单个和批量任务都遵守：

1. 校验名称、WAV 和台词。
2. 调用本地 Qwen 接口注册音色。
3. 注册成功后才写入 `voiceProfiles`。
4. 单行失败不影响其他行。

全部保存采用有限串行处理，避免同时唤醒多个后端请求或让浏览器存储产生覆盖竞争。

## 音色重命名

只有带完整本地 profile 的音色显示“重命名”。内置音色与兼容别名只读。

重命名采用数据安全优先的顺序：

1. 验证新名称不为空且未被占用。
2. 使用原 WAV、说话人数据和 `refText` 注册新名称。
3. 在一次存储更新中写入重命名后的 profile，并把 `opVoice`、`replyVoices` 中的旧名称替换为新名称。
4. 删除后端旧名称。

如果第 2 步失败，什么都不改变。如果存储更新失败，尽力删除刚注册的新名称并保留旧 profile。如果最后删除旧后端名称失败，新名称仍然保持可用，并在刷新或下次启动时再次尝试清理旧名称；不得因清理失败丢失用户音色。

## 错误呈现与恢复

- 错误必须显示在对应任务行，批量顶部只显示摘要。
- 网络失败提供“重试识别”；Qwen 注册失败提供“重新保存”。
- Edge 云识别不可用时，录音、上传、裁剪、试听、手动台词和保存仍然可用。
- 页面关闭前若仍有未保存任务，提示用户确认；已保存音色不受影响。
- 不在日志或控制台输出完整音频 Base64、完整参考台词或网页正文。

## 模块边界

为避免继续扩大现有 `voice-studio.js`，新增独立模块：

- `shared/audio-import.js`：格式检查、解码、下混、能量分析、片段选择、24 kHz WAV 输出。
- `shared/voice-naming.js`：默认名称、规范化和重名后缀。
- `shared/transcription.js`：Provider 接口、Edge Web Speech 实现、超时和错误分类。
- `shared/voice-library.js`：profile 规范化、批量状态和安全重命名辅助逻辑。
- `voice-studio.js`：只负责页面状态、事件绑定和模块编排。

后台新增明确的 `voice:rename` 消息，由 background 统一完成后端注册、存储设置修复和旧名称删除；页面不能自行拼装半事务流程。

## 验收测试

### 自动化测试

1. WAV、MP3 等可解码输入能输出 24 kHz 单声道 WAV。
2. 首尾静音被裁剪，长音频选择 10～15 秒稳定窗口，短于 5 秒被拒绝。
3. 文件名规范化和 `(2)`、`(3)` 重名分配稳定。
4. SpeechRecognition 最终结果正确合并，临时结果不会重复写入。
5. 临时错误最多重试两次，永久错误不重试，取消不触发自动重试。
6. 批量队列严格串行；单项失败不会终止其他任务。
7. 注册成功后才保存 profile；失败时不留下假成功记录。
8. 重命名同步更新楼主和回复音色配置，任一步失败都不会丢失旧音色。
9. 旧格式 `voiceProfiles` 仍能列出、同步和朗读。

### Edge 实机验收

1. 麦克风录制后自动识别中文台词并成功注册。
2. 一次选择多种支持格式，逐个生成名称、片段和台词。
3. 断网时自动重试并最终允许手动台词；恢复网络后单项重试成功。
4. 用户拒绝云识别或策略禁用时，不影响手动保存音色。
5. 批量保存后刷新扩展、重启网关，音色仍自动恢复。
6. 重命名当前楼主音色后，帖子朗读继续使用新名称。
7. 导入和识别期间不出现第二个托盘图标或额外开机启动项。

## 发布与兼容

- 更新扩展版本号并重新生成 `dist/Qwen-Reader-Edge`。
- 保持现有本地接口地址和可信客户端请求头不变。
- 不新增宽泛互联网 host permission；SpeechRecognition 由 Edge 自身提供。
- 如果运行时检测不支持音轨输入，UI 自动退化为手动台词模式，不使用播放到麦克风等不可靠绕行方案。
