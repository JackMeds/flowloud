# 论坛段落级朗读与用户滚动优先设计

## 目标

修复论坛长楼层被识别为单个朗读块的问题，并采用类似音乐播放器歌词页的跟随机制：播放器可以跟随当前朗读段落，但一旦用户手动浏览页面，播放器必须立即停止控制滚动，直到用户明确恢复跟随。

首个真实验收页面为 `https://bbs.viva-la-vita.org/d/48666`。该页面楼主正文当前包含 28 个非空 `<p>` 节点，扩展应将它们保留为可独立朗读、定位和高亮的语义段落。

## 已确认根因

当前论坛 API 适配器以“楼层”为单位生成 `NormalizedBlock`。一个楼层的完整 HTML 会先被压成纯文本，之后播放器只按最大字符数再次切片。字符切片继承相同的楼层级 `sourceSelector`，因此无法定位原页面中的具体段落。

播放器在每次朗读项变化时无条件调用 `scrollIntoView({ behavior: "smooth", block: "center" })`。该调用既不检查目标是否已经可见，也不判断用户是否刚刚滚动，因而会覆盖鼠标滚轮、触摸、键盘和滚动条拖动产生的用户意图。

## 范围

本次实现包含：

- Flarum、Discourse、NodeBB 和 XenForo 论坛正文的语义段落拆分。
- 每个段落的原页面定位、高亮和最小幅度跟随滚动。
- 手动滚动后进入“自由浏览”，并提供“回到当前朗读”按钮。
- 保持现有作者、楼层、楼主和音色分配规则不变。
- 自动化回归测试和真实 Flarum 页面结构验证。

本次不包含：

- 自动识别图片中的文字。
- 朗读图片文件名、尺寸、附件元数据或图片 `alt` 文本。
- 单词级或句子级高亮。
- Edge 原生侧边栏改造。
- 定时自动恢复跟随；恢复跟随必须由用户明确触发。

## 语义段落模型

### 拆分规则

论坛适配器先清理正文 HTML，再按以下语义节点生成段落：

- `p`
- `h1` 至 `h6`
- `li`

引用块、签名、操作栏、点赞区、徽章、广告、链接预览、附件元数据、图片和纯空白节点继续按现有过滤规则排除。纯图片段落不进入朗读队列。两三个字的短回复仍然保留，不设置最小字数阈值。

如果正文中不存在可用的语义子节点，适配器退回到当前的整楼层文本提取，以保证非标准论坛内容不会完全消失。

一个语义段落超过 TTS 最大字符数时，可以继续切成多个音频请求；这些请求共享同一个原文定位器，因此高亮仍对应原页面中的同一个段落。

### 元数据继承

同一楼层拆出的所有段落必须继承相同的：

- `postId`
- `floor`
- `authorId`
- `authorName`
- `isOp`

音色分配仍以作者和楼层为依据。拆分段落不得导致同一作者在同一楼层内切换音色，楼主专属音色也不得进入其他作者音色池。

### 段落定位器

`NormalizedBlock` 增加结构化 `sourceLocator`：

```js
{
  adapter: "flarum",
  containerSelector: ".PostStream-item[data-id=\"123\"] .Post-body",
  unitIndex: 4,
  fingerprint: "稳定文本指纹"
}
```

定位顺序为：

1. 在 `containerSelector` 内枚举经过相同过滤规则处理的语义节点。
2. 优先选择文本指纹匹配的节点。
3. 指纹未匹配时使用 `unitIndex`。
4. 两者均失败时退回楼层容器，但不抛错或中断播放。

文本指纹用于抵抗论坛 SPA 渲染产生的轻微节点变化，索引用于处理同文段落或指纹碰撞。定位器只包含本地页面结构信息，不会被发送到 TTS 服务。

## 高亮行为

- 当前朗读段落添加现有 `qwen-reader-speaking` 样式。
- 切换段落时移除上一段高亮。
- 同一原文段落被拆成多个音频请求时，不重复闪烁或重新滚动。
- 无法定位具体段落时允许退回楼层级高亮。
- 用户进入自由浏览后，高亮继续更新，但不得触发页面滚动。

## 跟随状态

播放器维护两个明确状态：

### `following`

- 默认状态。
- 当前段落已经位于可视区域安全范围内时不滚动。
- 当前段落离开安全范围时，使用 `scrollIntoView({ behavior: "smooth", block: "nearest" })` 做最小幅度移动，不再强制居中。
- 同一个原文段落的后续字符切片不重复滚动。

### `manual`

以下用户意图会立即切换到自由浏览：

- 鼠标滚轮。
- 触摸滚动。
- PageUp、PageDown、Home、End、方向上、方向下或空格滚页。
- 在浏览器滚动条区域按下并拖动指针。

进入 `manual` 后：

- 音频继续播放。
- 当前段落继续高亮。
- 所有自动滚动调用被禁止。
- 面板显示“回到当前朗读”按钮。
- 不使用定时器自动恢复跟随。

点击“回到当前朗读”后：

1. 状态切回 `following`。
2. 立即将当前高亮段落以最小幅度滚入可视区域。
3. 隐藏恢复按钮。

重新扫描新页面或开始一条全新的朗读队列时恢复为 `following`。暂停后继续播放不改变当前跟随状态。

## 用户界面

“回到当前朗读”使用紧凑的次级按钮，放在现有播放控制区域附近，仅在以下条件同时满足时显示：

- 有正在播放或暂停中的朗读队列。
- 跟随状态为 `manual`。

按钮不遮挡正文，不创建新的弹窗，也不自动展开收起的侧面板。悬浮提示和无障碍名称统一为“回到当前朗读”。

## 组件边界

### 论坛语义单元提取器

负责将清理后的论坛 HTML 或 DOM 转换为语义单元，输出文本、索引和指纹。它不了解播放状态和音色。

### `NormalizedDocument`

负责保存 `sourceLocator` 并在字符切片时完整继承定位信息。它不访问页面 DOM。

### 源节点解析器

根据 `sourceLocator` 在当前页面查找具体段落，并提供楼层级回退。它不执行滚动。

### 跟随控制器

负责 `following/manual` 状态、用户意图事件和是否允许滚动的纯策略判断。它不负责正文提取或音频播放。

### 阅读器界面

负责高亮、调用源节点解析器、在允许时执行最小滚动，以及显示或隐藏“回到当前朗读”。

## 动态页面处理

Flarum、Discourse 和 NodeBB 的 SPA 导航或增量加载仍沿用现有重新扫描机制。重新扫描时定位器根据新 DOM 重新解析，不保存失效的元素引用。

如果播放期间新增回复，仅为新内容生成定位器；现有队列中仍能按 `postId + fingerprint + unitIndex` 重新找到当前段落。

## 错误处理

- 单个段落定位失败：退回楼层级高亮，不中断朗读。
- 楼层容器也不存在：继续播放，但跳过高亮和滚动。
- 指纹出现重复：优先采用与 `unitIndex` 最接近的匹配节点。
- 页面在平滑滚动期间被用户操作：用户意图优先，立即进入 `manual`；后续段落不得继续滚动。
- 面板关闭或扩展停止：移除高亮和临时事件状态，不保留页面样式。

## 测试与验收

### 自动化测试

1. Flarum API 中一个楼层含多个 `<p>` 时生成多个 block。
2. 每个 block 保留相同作者、楼层、楼主和音色所需元数据。
3. 纯图片段落、图片元数据、引用块和操作控件不进入朗读文本。
4. 两三个字的独立段落被保留。
5. 长语义段落做字符切片后仍继承同一 `sourceLocator`。
6. 源节点解析器优先按指纹定位，索引和楼层回退可用。
7. 已可见段落不会触发滚动；不可见段落在 `following` 状态使用 `nearest` 滚动。
8. wheel、touch、键盘滚页和滚动条拖动会进入 `manual`。
9. `manual` 状态下切换高亮但滚动调用次数保持为零。
10. 点击“回到当前朗读”恢复跟随并只执行一次定位滚动。
11. 暂停/继续保持手动状态；新页面或新队列重置为跟随状态。

### 真实页面验收

在 `https://bbs.viva-la-vita.org/d/48666` 上验证：

- 楼主的 28 个非空 `<p>` 被识别为 28 个可独立定位的语义段落，只有超长单段允许进一步生成多个音频请求。
- 当前段落单独高亮，播放下一段时高亮移动到对应 `<p>`。
- 用户滚轮向上或向下浏览后，播放继续但页面不再被拉回。
- “回到当前朗读”能返回当前段落并恢复后续跟随。
- 楼主全部段落保持楼主专属音色，其他作者不获得该音色。

## 安全与隐私

本次变更不增加网络权限、不新增远程服务，也不改变正文仅发送到 `127.0.0.1:7811` 的现有边界。用户滚动事件只用于本页跟随状态判断，不记录、不持久化，也不发送到任何服务。
