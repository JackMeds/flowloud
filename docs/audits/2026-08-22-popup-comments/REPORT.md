# Popup 与网页悬浮播放器体验审计

- 日期：2026-08-22
- 模式：UX + 可访问性初审
- 用户目标：在不进入完整设置页的情况下，快速控制朗读、点读、悬浮播放器与论坛角色配音，并持续看见当前朗读位置。
- 环境：Codex in-app Browser；Storybook；1376 × 1216；DPR 1.5。
- 路由：`flowloud-popup-console--playing`、`flowloud-floating-player--expanded`、`flowloud-floating-player--orb`。

## 体验健康度

当前视觉语言已经统一到中性蓝白，但信息架构和核心任务入口仍不合格。整体可作为组件草图，尚不能作为最终 Popup 方案。

## 关键证据

1. 三个页签虽然等宽，但计算样式是 `text-align: start`，因此标签文字没有被明确居中；这是组件约束缺失，不是主观错觉。
2. 两个开关轨道的右边缘与容器右边缘完全重合，实测右侧留白为 `0px`，打开后视觉上更显得贴边。
3. “本页音色”把算法选择误做成逐作者手工指定，增加论坛多人场景的操作负担。
4. “朗读设置 / 即时生效”没有提供可执行信息，消耗了小窗首屏空间。
5. “设置”页重复了顶部“全部设置”和“朗读”页里的入口，职责重叠。
6. 旧版网页正文和迷你字幕具备共享逐词时间线；当前 React Popup 只渲染静态 `currentText`，Storybook 尚不能演示动态逐词跟随。

## 建议结构

### 播放器下方固定快捷区

- 点读：始终可见的状态按钮。
- 悬浮播放器：始终可见的状态按钮。
- 回到正文：朗读中显示。

### 页签只保留两个

1. 朗读
   - 语音来源
   - 播放速度
   - 正文朗读 / 页面导览
   - 角色配音策略
   - 楼主声音
   - “高级：逐角色指定”二级入口
2. 外观
   - 浅色 / 深色 / 跟随系统
   - 当前句聚焦方式
   - 逐词效果
   - 字号与高亮强度
   - 快捷键提示与完整设置入口

### 角色配音策略

1. 所有人同一声音
2. 楼主独立，其他人同一声音
3. 楼主独立，其他作者按稳定随机序列分配
4. 楼主独立，其他作者按声音列表顺序循环分配

随机策略应基于页面与作者生成稳定种子，避免刷新后声音变化。只有楼主声音在一级界面手工指定；逐作者覆盖进入二级页面。

## 可访问性边界

当前语义结构包含 tab、tabpanel、region 和带名称的按钮，44px 悬浮球也满足基本触控尺寸目标。尚未完成键盘全流程、焦点可见性、缩放重排、屏幕阅读器状态播报和颜色对比验证，因此不能据此声称满足完整 WCAG 要求。
