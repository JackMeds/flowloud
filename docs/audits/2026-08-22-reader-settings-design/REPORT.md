# 网页朗读层与完整设置中心设计审计

- 日期：2026-08-22
- 范围：网页正文逐词高亮、朗读定位反馈、完整设置中心
- 用户目标：在不破坏网页排版的前提下持续知道读到哪里，并能在完整设置页统一管理引擎、声音、多人配音、外观与快捷键。
- 环境：Codex in-app Browser；本地 reader harness 与 Storybook。

## 体验健康度

- 网页朗读层：功能链路已存在，但当前词与当前句的视觉反馈过弱，暂停、减弱动画和离屏状态缺少清晰的视觉规格。
- 完整设置中心：基础侧栏和页面骨架可保留，但信息架构不完整、内容密度过低，保存模式也不够明确。

## 网页朗读层

建议使用三层反馈，而不是用一个强烈发光效果包办所有状态：

1. 当前句：极浅蓝色纸张洗色或细底线，不改变网页布局。
2. 当前词：蓝色文字强调与一次性轻扫光标，播放时移动、暂停时冻结。
3. 位置与身份：正文侧边显示作者/声音标记；当前句离开视口时才显示迷你字幕与“回到正文”。

系统减少动态效果时关闭轻扫动画，但保留静态当前词底线。正文标记优先使用 CSS Highlight API，保留无布局位移的 DOM fallback。

## 完整设置中心

建议保留左侧导航骨架，重组为：

1. 朗读与交互：默认速度、正文朗读、点读、悬浮播放器。
2. 语音来源：浏览器系统语音、浏览器模型、本地 Qwen、在线兼容 TTS，附连接与隐私状态。
3. 声音库：声音搜索、筛选、试听、导入与默认声音。
4. 角色配音：默认配音算法、楼主声音、回复声音池、逐角色覆盖。
5. 阅读外观：主题、当前句聚焦、逐词效果、颜色/强度/速度和实时预览。
6. 快捷键：播放、暂停、前后句、点读、回到正文与自定义冲突提示。
7. 高级：模型存储、清理缓存、诊断与重置。

设置中心应采用自动保存并在页面顶部显示“已保存”，移除同时出现的禁用“保存更改”按钮。阅读外观页需要一个固定的实时预览区，控件修改后立即在示例正文上显示效果。

## 证据限制

截图可以判断层级、密度和可见反馈，但不能证明键盘焦点、屏幕阅读器播报、真实网页兼容性、滚动跟随稳定性或完整 WCAG 合规；这些需要交互原型和真实论坛页面验证。
