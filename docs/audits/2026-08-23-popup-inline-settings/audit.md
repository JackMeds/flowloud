# Popup 内联设置体验审计

## 审计范围

- 表面：Flowloud React Popup，420 × 600。
- 任务：调整常用声音、阅读外观与本页作者配音。
- 目标：日常设置不离开 Popup；常见内容量下不显示功能区滚动条。

## 流程与健康度

1. 声音设置（修复前）：功能区只有约 173px，高度不足，声音卡片产生独立滚动条。健康度：差。
   - 证据：[01-current-sound.png](01-current-sound.png)
2. 配音设置（修复前）：楼主声音与逐角色指定都是跳页入口；真实扩展可能因页面编辑上下文失效而报错。健康度：差。
   - 证据：[02-current-voices.png](02-current-voices.png)
3. 配音设置（修复后）：功能区约 249px；策略、楼主和两位回复作者全部在 Popup 内显示并可直接选择。三位作者时无滚动条。健康度：良好。
   - 证据：[06-inline-voices-final.png](06-inline-voices-final.png)
4. 阅读外观（修复后）：句子聚焦和逐词效果继续使用 Popup 内二级视图，不打开新页面。健康度：良好。
   - 证据：[07-inline-appearance.png](07-inline-appearance.png)

## 关键结论

- 结构问题不是 Popup 总高度不足，而是播放器与快捷操作占用了过多固定高度，导致下方出现一个狭窄的二次滚动区域。
- 常用配音不应依赖临时 `contextId` 的新页面；Popup 已经持有来源标签页与页面身份，可以直接通过现有 `reader:page-voices:get/apply` 协议读取和保存。
- 浏览器最大 Popup 高度仍为 600px。超过常见作者数量时保留功能区滚动作为必要降级；三位作者和其余常用页签不显示滚动条。

## 可访问性与证据限制

- 页签、选择器和返回按钮保留可访问名称，键盘可聚焦。
- 本次已验证 DOM 语义、可见布局、选择器状态变化和生产协议构建；未在用户已安装的 Edge 扩展实例中执行重新加载后的人工视觉验收。
